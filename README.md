# UAZ 4x4 Widescreen UI Patch

**Патчер для Полный привод: УАЗ 4x4**
Исправляет отображение интерфейса при соотношениях сторон, отличных от 4:3, за счёт изменения логики отрисовки UI. Работает так же для Полный привод 2(и, скорее всего, для остальных игр с текущим движком и фреймворком, выпущенных ASE)

## Как это работает

Игра размещает меню и HUD в экранных координатах от 0 до 1 и умножает X на полную ширину
экрана. На экранах 16:9 и шире из-за этого все текстуры интерфейса, которые берутся из
текстурных атласов игры, растягиваются по горизонтали.

## Изменения 
- Сейчас немного пофикшены положения текстов на HUD в гонке, в главном меню и в меню опций(Файлы из `Data\Menu\scr\`). Пофикшен HUD штрафных очков для уральского триала руками, что скорее всего ломает отображение на 4:3 экране, не проверял
- исправлен баг с сортировкой травы, трава использовала некорректный слот, из-за чего деревья и другие объеты всегда отрисовывались перед травой(`rain_drops\fixes\_Grass.mtt|_GrassLit.mtt`). Они устанавливаются через скрипт `install.ps1`. Если остальные эффекты не нужны, можно просто закинуть их в `Data\Shaders`
- Так же была найдена опечатка в файле маппинга материалов призрака для Уаз Хантер(класс C). Это приводило к тому, что при формирования машины для бота-призрака вместо "призрачного" материала подставлялся материал обычного бампера. Поскольку обычный материал требует так же привязки динамической кубмапы(для формирования отражений от него), а машина призрак такого материала не имеет, то это могло привести к вылетам. Это оригинальный баг игры, во второй части в том же конфиге есть такая же опечатка в `Data\cars\3UH\Parts\3UH_BumperF.skn`
- пофикшены кубмапы для эффекта отражения воды, в базе игра использовала стандартную кубмапу с ясной погодой для отражений, исправил на использование пасмурной

Перед установкой проделать п1. установки(патчер читает оригинальные файлы из `code.pak.bak` и `code_inf.pak.bak` и из них патчит основные).

## Требования
- Желательно издание "Полный привод: Весь УАЗ", т.к. в нём отсутствует Starforce DRM

**Необязательно, но рекомендуется**:
- [DXVK](https://github.com/doitsujin/dxvk): 32-битный `d3d9.dll` рядом с
  `4x4game.exe`. Исправляет вылеты в полноэкранном режиме (`D3DERR_DEVICELOST`).
- [Large Address Aware Patcher](https://ntcore.com/files/4gb_patch.zip) для патча 4x4game.exe для использования 4GB адресного пространства(уменьшит вылеты на современных системах)

Для сборки через `build.ps1`:

- **Windows PowerShell 5.1 или PowerShell 7.**
- **JDK 8** (`javac`, `java`). Более новые JDK не умеют собирать под Java 1.4. Путь по умолчанию
  в `build.ps1`: `C:\Program Files (x86)\RedHat\java-1.8.0-openjdk-1.8.0.372-1\bin`.
- **ASM 5.1**: `asm-5.1.jar` и `asm-tree-5.1.jar`. Путь по умолчанию: папка `tools\lib`
  в Android SDK. Их также можно скачать из Maven Central (`org.ow2.asm`).
- **Оригинальные, непропатченные pak-файлы**, сохранённые как `code.pak.bak` и `code_inf.pak.bak`
  в папке игры. Патчер всегда берёт файлы из этих копий.

Если JDK 8 или ASM лежат в другом месте, измените пути `$jdk` и `$asm` в начале `build.ps1`.

## Установка / пересборка

1. При первой установке сделайте резервную копию оригиналов(через PowerShell или руками):
   ```powershell
   Copy-Item <GAME INSTALL DIR>\code.pak     <GAME INSTALL DIR>\code.pak.bak
   Copy-Item <GAME INSTALL DIR>\code_inf.pak <GAME INSTALL DIR>\code_inf.pak.bak
   ```
2. Скопируйте папку `widescreen_patch` в папку игры.
3. Запустите:
   ```powershell
   <GAME INSTALL DIR>\widescreen_patch\build.ps1
   ```
   Сборка должна закончиться строкой `patched classes: 13`.

## Удаление

```powershell
Copy-Item <GAME INSTALL DIR>\code.pak.bak     <GAME INSTALL DIR>\code.pak     -Force
Copy-Item <GAME INSTALL DIR>\code_inf.pak.bak <GAME INSTALL DIR>\code_inf.pak -Force
```

## Настройка

Измените эти константы в `UIAspect.java`, затем снова запустите `build.ps1`:

| Константа | По умолчанию | Значение |
|---|---|---|
| `FULL_WIDTH` | `0.95` | Элементы шире этого значения (в логических единицах игры) растягиваются на весь экран |
| `HUD_LEFT_EDGE` | `0.4` | Элементы HUD, центр которых левее этого значения, прижимаются к левому краю |
| `HUD_RIGHT_EDGE` | `0.6` | Элементы HUD, центр которых правее этого значения, прижимаются к правому краю |

## Настройки живут в mods.ini в корне игры

Достаточно изменить значение и перезапустить игру

| Section | Keys |
|---|---|
| `[widescreen]` | `aspect` (масштабирование UI в 4:3), `resolution_list` (все доступные разрешения дисплея), `fov`(FOV-коррекция для широкоэкранных разрешений), `view_distance`(коррекция дальности отрисовки из-за изменения FOV), `view_distance_mul` (мультипликатор дальности) |
| `[cockpit]` | `look_turn`(В камере из кабины камера подворачивает за рулём в сторону поворота), `look_turn_angle`(макс угол поворота камеры в градусах), `look_turn_speed`(скорость поворота камеры) |
| `[glass_drops]` | `enabled`(Капельки дождя на лобовом(**WIP, ТОЛЬКО НА ПЕРВУЮ ЧАСТЬ**)), `accel`(множитель реакции на ускорение/торможение), `bump`(реакция на ухабы) |
| `[wetness]` | `enabled`(Мокрый террейн и лужи (**WIP, ТОЛЬКО НА ПЕРВУЮ ЧАСТЬ**)) в ямах террейна и дорогах, `puddles`(кол-во луж), `force`(интенсивность эффекта(-1 - следует игровой логике, т.е работает только на картах с дождем)) |
| `[water]` | `camera`, `trees_lod`, `objects_lod`, `tree_refl_call` |
| `[build]` | `RainFX`, `CockpitLook`: глобальные переключатели для эффектов дождя и камеры при запуске скрипта патчинга Java `build.ps1`. Выставить на 0, если требуется только широкоэкранный патч |

Секция `[install]` относится к скрипту `rain_drops\install.ps1`. Скрипт перезапишет нужные игровые шейдеры и добавит свои. Если ключа нет, берется значение по умолчанию(вкл). После изменений желательно заново запустить скрипт

Параметры капель задаются в `rain_drops\OnFrontGlass_Rain.fx` перед запуском скрипта. Если не охота перезапускать скрипт установки, `Data\FX\FXDEF\glass\OnFrontGlass_Rain.fx` игры:
```HLSL
GlassMarksDef()
{
  MarkLifeTime()
  {
    keyf(0, 5) // TTL капли
  }

  MarkSize() // увеличение капель с течением времени
  {
    randf(0, 0.1, 0.6)
    randf(4, 0.9, 1.3)
    randf(5, 2.4, 4.5)
  }

  MarkColor()
  {
    keyv4(0, 1, 1, 1, 1)
    keyv4(1, 1, 1, 1, 1)
    keyv4(3, 1, 1, 1, 0.4)
    keyv4(4, 1, 1, 1, 0.1)
    keyv4(5, 1, 1, 1, 0)
  }

  MarkMaterial("OnFrontGlass_Rain.mat")
  MarksRate(150) // количество капель 
	MarksMaxSpeed(5) // скорость соскальзывания
	MarkMoveProbability(0.3) // кол-во капель, которые соскользнут(от общего)
	SweepMaterial("OnFrontGlass_RainSweep.mat")
	MarkTexcoords(2,2,4)
}
```

    - `Data\mapscustom\level2\Level2.height`
    - `Data\mapscustom\level2\level2_01.height`(?)
    - `Data\mapscustom\level3\level3.height`
    - `Data\mapscustom\Taiga\Taiga.height`
    - `Data\mapscustom\ural\ural.height`
    - `Data\mapscustom\uraltrial2\UralTrial2.height`(?)
    - `Data\mapscustom\uraltrial3\UralTrial3.height`(?)
    - `Data\mapscustom\uraltrial4\UralTrial4.height`(?)
    - `Data\mapscustom\uraltrial5\uraltrial5.height`(?)
  
  К примеру, `python terrain_tools\uaz_height_upsample.py --factor 2 Data\mapcustom\level1\level1.height` увеличит разрешение карты высоты для карты в Средней Полосе. Можно передать несколько путей через пробел, в таком случае будут обработаны несколько файлов. Скрипт сохраняет оригинальный файл в `*.height.orig` и меняет значения из него. Вернуть как было можно через ключ `--restore` с указанием пути до `.height` файла
